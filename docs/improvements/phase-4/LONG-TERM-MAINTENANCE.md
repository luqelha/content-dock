## Lifecycle dependency dan upgrade

```powershell
npm run maintenance:dependencies
npm run maintenance:dependencies:registry
npm run audit:dependencies
```

Script pertama membaca lockfile: 95 deklarasi langsung (paket yang dipakai dua workspace dihitung dua kali), versi resolved, range, engines dan deprecated metadata yang tersedia di lock. Tidak ditemukannya `deprecated` di lock bukan bukti registry tidak mendeprecate paket. Mode registry menambahkan `npm outdated` dengan `current/wanted/latest`; `latest` adalah dist-tag dan dapat berupa prerelease. Query gagal menghasilkan status unavailable dan exit nonzero. Tidak ada update dependency otomatis. Snapshot memiliki hash lock dan waktu UTC; `wanted` mengikuti range, bukan selalu versi yang ingin kita deploy.

Kebijakan machine-readable ada pada `ops/maintenance/dependency-lifecycle.json`, owner Platform maintainer, review berikutnya sebelum 13 November 2026. Gate menolak Node major di luar window support yang direview atau policy expired. Node **24** dipakai CI/Docker dan `.node-version`; Node 22.12+ tetap kompatibilitas lokal sampai migrasi, EOL 30 April 2027 dengan target migrasi 31 Januari 2027. Node 24 EOL 30 April 2028, target migrasi 31 Januari 2028. Jadwal diperiksa terhadap [Node Release schedule](https://github.com/nodejs/Release/blob/main/schedule.json); patch terbaru tetap perlu review keamanan, major yang masih didukung tidak menjamin patch lama aman. npm dipatok **10.9.9** melalui packageManager dan install eksplisit CI; tidak mengubah npm global workstation.

Urutan upgrade: satu track/PR, baca docs versi target, ubah manifest dan root lock secara konsisten, `npm ci`, generate Prisma bila perlu, jalankan pemeriksaan sesuai dampak. API/DB/queue memerlukan integration, E2E, grants dan recovery; web/editor memerlukan matrix browser/axe dan manual bila interaksi berubah. Security patches diprioritaskan, major perlu compatibility/rollback plan. Jangan menjalankan `npm audit fix --force` atau memperbarui snapshot kontrak tanpa meninjau wire format.

Rollback dependency mengembalikan manifest dan root lock sebagai pasangan, clean install, rebuild artifact dan rerun gate. Database migration harus memiliki rencana kompatibilitas tersendiri; mengembalikan package saja bukan rollback schema. Perubahan library keluarga tidak dicampur sembarangan antara image API/web/worker.
